## Summary

Correctness is closed at T016=RESOLVED_NO_CHANGE; T026 physical acquisition is complete and its overshoot/output divergence remain recorded. The remaining T027 question is product performance: explain the end-to-end real coding-agent time difference between production Qwen3.8-27B-4bit + its generic production DFlash2 + plain target KV + adaptive production serving and local Bonsai2 ternary + its appropriate generic DFlash2 + plain KV + adaptive DFlash. The maintainer confirms 4-bit Qwen fits at 262144 context with plain KV, so target KV stays plain and the Bonsai target's ternary format is already the compression tradeoff. T027 is a single causal A/B, not a KV precision or broad operating-point sweep.

The plan does not assume the rollback formula, the installed gated-delta recurrence, or mlx-lm source skew is defective. Both runtimes use byte-identical mlx-lm source and the same gated-delta callable, but Chad's Prism fastpath changes the projection/op graph before that callable, so equal implementation identity does not establish equal inputs or logits. The implementation path is gated: identify the first differing boundary, add a deterministic regression that exposes it, and make one minimal mlx-dspark change only if within-runtime evidence identifies a production behavior defect. T016 records only the initial localization result: FIX_PENDING (the earliest controlled mlx-dspark defect is localized and exactly one T019–T022 causal regression/patch branch is authorized), RESOLVED_NO_CHANGE (all reachable required correctness gates are conclusive and establish no production patch is required), or UNRESOLVED (required evidence remains inconclusive and no production patch is authorized). T016 never records RESOLVED_FIX. If FIX_PENDING, exactly one T019–T022 branch establishes the causal regression, T023 makes the single demonstrated production change, and T024 reruns the regression and required validation; only after successful applicable work may T024 finalize RESOLVED_FIX. Failure to establish the regression, failed validation, or inconclusive required evidence yields final UNRESOLVED. When T016 is RESOLVED_NO_CHANGE, preserve that outcome through T024/T030. T030 carries the finalized investigation outcome. UNRESOLVED is not a successful no-production-change result: it authorizes no production patch, requires the missing evidence/control and unresolved gate to be recorded, and forbids claiming SC-003/Definition-of-Done completion. Evidence may be preserved and reproducible hardware commands prepared.

## Post-correctness product operating-point evaluation

Correctness localization and product operating-point selection are separate phases. Through the causal gates and any applicable fix validation, target quantization, target-KV precision, scheduler thresholds, selector math, and kernel choices are controlled variables rather than ways to force parity.

After deterministic correctness and the exact golden hardware validation, the maintainer may intentionally compare multiple mlx-dspark operating points. The primary matrix is:

1. Established Qwen3.8 27B 4-bit target + generic DFlash2 baseline using the production server configuration.
2. Ternary Bonsai target + plain target KV + the exact generic Chad-built DFlash2 sidecar.
3. Ternary Bonsai target + quantized target KV + that same sidecar.
4. Optionally, 4-bit target + quantized target KV if supported and useful for the memory comparison.

For Bonsai, fixed7 remains an execution/performance control and adaptive mode is evaluated separately. Record observed cache class/precision, exact model and sidecar identity, acceptance and widths, target forwards, decode throughput, prefill/TTFT, peak memory, context-window configuration, and prefix-cache conditions. The purpose is to choose a speed/memory/context operating point, not to reinterpret earlier correctness evidence. Historical Chad or mlx measurements may motivate a candidate but never substitute for a fresh measured M4 result.

The target-specific Bonsai sidecar was measured once as the final T027 control after fresh production-path evidence localized the product loss to proposal agreement. It modestly improved speculative efficiency but did not approach Qwen throughput; T027 is final and no further operating points are requested.

No M4 Pro commands were run while preparing this plan.
